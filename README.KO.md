# DS5Dongle: 스위치 프로 + 스위치 2 깨우기 포크

[English](./README.md)

Raspberry Pi Pico 2 W로 DualSense(DS5)를 무선 연결하는 [awalol/DS5Dongle](https://github.com/awalol/DS5Dongle)에 **닌텐도 스위치 모드**를 추가한 포크입니다.

- 스위치나 스위치 2 독에 꽂으면 DualSense가 **유선 프로콘**으로 인식됩니다.
- 스위치 2가 절전 중일 때 **PS 버튼으로 본체를 켤 수 있습니다.**
- PC 모드는 원본과 같습니다.

> 비공식 프로젝트이며 닌텐도·소니와 관계없습니다. 상표는 각 소유자의 것이고, VID/PID와 장치 이름은 상호운용 목적으로만 사용합니다.

## 기능

| 기능 | 설명 |
|---|---|
| 스위치 프로 모드 | USB `057E:2009`(프로콘). 버튼은 위치 기준(✕=B, ○=A). 자이로를 지원하고, HD 진동을 DualSense 햅틱으로 변환함 |
| 모드 전환 | **Create + Options + 음소거 2초** → 스위치 프로 ↔ PC(Auto). 설정 저장 후 재부팅(Pico LED: 스위치 2회, PC 1회 깜빡임). 재부팅 후 PS로 다시 연결 |
| 매크로 (스위치 모드) | 슬롯 4개: 음소거 + ○/✕/△/□. 아래 [매크로](#매크로) 참고. PC 매니저에서 단계별로 편집 가능 |
| 연사 (스위치 모드) | **음소거 + 버튼 더블탭**(○✕△□, L1/R1/L2/R2)으로 켜고 끔, **음소거만 짧게** 누르면 모두 끔. 아래 [연사](#연사-터보) 참고 |
| 진동 세기 (스위치 모드) | **음소거 + ↑/↓** → 0~5단계(0 = 끔, 20% 단위). 기본 3단계(60%). DS5 플레이어 LED 개수로 표시. PC 매니저에서는 1% 단위 |
| 트리거 모드 (스위치 모드) | **음소거 + →/←** → 1 일반, 2 딸깍, 3 짧게, 4 오토매틱. 음소거 LED 깜빡임 횟수로 표시. PC 매니저에서 모드마다 L2/R2 효과와 입력 지점을 따로 편집 가능 |
| PC 매니저 | [DS5 Dongle Manager](https://github.com/DoorWarning/ds5_dongle_manager): PC/NS 모드 전환, PC 설정, NS 설정(진동·트리거·연사·매크로), 깨우기 비컨 학습 |
| 스위치 2 절전 깨우기 | 본체 절전 중 PS → 본체가 켜짐 → **PS 한 번 더**로 DualSense 재연결 |

스위치 2에서 쓰려면 본체 설정에서 **컨트롤러와 센서 → 프로콘 유선 통신**을 켜 주세요.

## 사용법

### 페어링과 BOOTSEL 버튼 (원본과 같음)
- 페어링: BOOTSEL 1번 → DualSense **Create + PS**를 라이트바가 빠르게 깜빡일 때까지 누름. 이후에는 PS만 눌러도 다시 연결됩니다.
- BOOTSEL 1번: 연결 끊기, 또는 30초 동안 검색
- BOOTSEL 2번: 재부팅
- BOOTSEL 3번: 펌웨어 업로드 모드(UF2 드라이브)
- BOOTSEL 1.5초: 저장된 페어링 전부 삭제

### 매크로
음소거를 누르고 있는 동안에는 ○✕△□와 L1/R1/L2/R2가 스위치로 전달되지 않습니다.
- **녹화**
  1. 음소거 + 슬롯 버튼을 **3초** 누릅니다. 음소거 LED가 천천히 깜빡이면 녹화 대기 상태입니다.
  2. **모든 버튼에서 손을 떼는 순간** 녹화가 시작됩니다. 버튼과 스틱이 녹화되고, 자이로는 녹화되지 않습니다.
  3. **음소거만 누르면** 녹화가 끝나고 저장됩니다.
- **1회 재생:** 음소거를 누른 채 슬롯 버튼을 짧게(1초 미만) 눌렀다 뗍니다. 더블탭(연사)인지 확인하느라 0.3초 뒤에 시작합니다.
- **반복 재생:** 음소거를 누른 채 슬롯 버튼을 1~3초 누르다 뗍니다. 반복하는 동안 음소거 LED가 켜져 있습니다.
- **정지:** 음소거만 누릅니다.
- **슬롯 지우기:** 녹화 대기(음소거 + 슬롯 버튼 3초) → 모든 버튼에서 손을 뗌 → **아무 입력 없이 바로 음소거**. 동작이 0개인 녹화는 빈 슬롯으로 저장됩니다. 4개를 한 번에 지우는 기능은 없습니다.
- 재생할 때 슬롯 버튼은 음소거를 누른 상태에서 떼야 합니다. 음소거를 먼저 떼면 취소됩니다.
- 녹화 시작 전의 입력 없는 구간은 잘라냅니다. 마지막 입력부터 음소거를 누를 때까지의 시간은 남아서 반복할 때 간격이 됩니다.
- 한 슬롯에 약 340개 동작(버튼 변화나 스틱 이동)까지 들어가고, 저장한 매크로는 재부팅해도 남습니다.
- 재생 중에 직접 누른 입력은 매크로 출력과 **합쳐져서 스위치로 전달**됩니다(버튼은 둘 다, 스틱은 매크로가 움직이는 동안 매크로 값). 이 입력이 슬롯에 저장되지는 않습니다. 슬롯은 녹화나 PC 매니저 편집으로만 바뀝니다.
- PC 매니저에서는 단계마다 시간, 버튼, 양쪽 스틱을 편집하고 단계를 추가·삭제·복제·이동할 수 있습니다. 동글이 NS 모드로 PC에 연결되어 있어야 합니다.

### 연사 (터보)
- **켜기/끄기:** 음소거를 누른 채 ○✕△□ 또는 L1/R1/L2/R2를 0.3초 안에 **두 번** 누릅니다. 켜지면 짧게 진동하고 음소거 LED가 2번, 꺼지면 1번 깜빡입니다.
- **모두 끄기:** 아무것도 재생 중이 아닐 때 음소거만 짧게 누릅니다(재생 중이면 재생만 멈춥니다).
- 연사가 켜진 버튼은 누르고 있는 동안 초당 10번(기본) 눌렀다 뗍니다. 속도(초당 2~30번)와 연사 버튼은 PC 매니저에서도 바꿀 수 있습니다.
- ○✕△□ 더블탭은 매크로 1회 재생과 같은 조합이라, 1회 재생은 두 번째 탭을 0.3초 기다린 뒤 시작합니다.
- 설정은 플래시에 저장되어 재부팅 뒤에도 유지됩니다.

### 진동 세기와 트리거 모드
독에 꽂힌 상태에서는 PC 설정 페이지를 쓸 수 없어서 컨트롤러로 바꿉니다. 동글을 NS 모드로 PC에 연결하면 PC 매니저에서도 바꿀 수 있습니다. 바꾸고 3초 뒤 플래시에 저장되고 재부팅해도 유지됩니다.
- **음소거 + ↑/↓**: 진동 세기 0~5단계(0 = 끔, 1~5 = 20~100%, 기본 3).
  - 바꾸면 DS5 플레이어 LED가 단계 수만큼 2초 동안 켜지고, 바뀐 세기로 짧게 진동합니다.
  - 5단계가 예전 세기와 같습니다. 0단계에서는 진동 데이터를 아예 보내지 않아 배터리도 아낍니다.
- **음소거 + →/←**: 트리거 모드 다음/이전. 음소거 LED가 모드 번호만큼 깜빡입니다.

| 모드 | 느낌 | ZL/ZR 입력 지점 |
|---|---|---|
| 1 일반 (기본) | 저항 없이 끝까지 눌림 | 거의 누르자마자 (DS5 버튼 신호 또는 아날로그 32 초과) |
| 2 딸깍 | 저항이 걸렸다가 딸깍 하고 넘어감 | 딸깍하는 지점 (아날로그 약 100) |
| 3 짧게 | 조금만 눌리고 강한 저항에 막힘 (버튼처럼) | 막히기 직전 (아날로그 약 30) |
| 4 오토매틱 | 누르면 트리거가 연사하듯 진동 | 진동이 시작되는 지점 (아날로그 약 20) |

트리거 효과는 DualSense 적응형 트리거의 원시 효과(`0x02` 구간, `0x01` 저항, `0x06` 진동)를 쓰며, [ds.daidr.me](https://ds.daidr.me) 테스터와 같은 인코딩입니다.

### 스위치 2 깨우기
1. **처음 한 번 학습.** 동글은 **PC나 충전기에** 꽂아야 합니다(독에서는 안 됨, 아래 참고).
   1. DualSense를 연결하고 **Create + Options + △를 3초** 누릅니다. Pico LED가 천천히 깜빡입니다(60초 대기).
   2. 본체를 절전시키고, **분리한 조이콘 2**의 HOME을 누릅니다.
   3. LED가 빠르게 5번 깜빡이면 저장된 것입니다. 저장한 내용은 재부팅이나 펌웨어 업데이트 뒤에도 남습니다.
2. **사용.** 동글을 독에 꽂고 스위치 모드로 씁니다.
   1. 본체가 절전 중일 때 **PS**를 누르면 LED가 3초 동안 빠르게 깜빡이고 본체가 켜집니다.
   2. 이어서 **PS를 한 번 더** 누르면 DualSense가 연결됩니다.

| Pico LED | 의미 |
|---|---|
| 천천히 깜빡 | 학습 모드, 비컨을 기다리는 중 |
| 빠르게 5번 | 비컨 저장 완료 |
| 3초 동안 빠르게 | 깨우기 비컨 송신 중 |
| PS 직후 빠르게 2번 | 본체는 절전 중인데 학습된 비컨이 없음 |

## 동작 원리와 확인된 사실

### 왜 비컨인가
- 유선 프로콘(스위치 1용)으로는 스위치 2를 절전에서 깨울 수 없습니다.
- 스위치 2는 조이콘 2·프로콘 2가 HOME을 누를 때 보내는 **BLE 광고(깨우기 비컨)**로 깨어납니다.
  - 비컨은 암호화돼 있지 않습니다.
  - 대신 본체와 페어링된 컨트롤러의 **공개(public) 주소**에서 보내야 합니다.
  - 형식은 [alexvnesta/switch2controller](https://github.com/alexvnesta/switch2controller)의 분석과 같습니다.

```
02 01 06 | 1B FF 53 05 01 00 03 7E 05 [PID 2B] 00 01 [플래그] [본체 BT 주소, 역순 6B] 0F 00 00 00 00 00 00 00
```
- 플래그: 평소 `00`, 깨울 때 `81`.

### 동글이 하는 일
1. 학습 모드에서 BLE 수신 → 조이콘 2 비컨(송신 주소 + 31바이트)을 플래시에 저장
2. 스위치 모드에서 본체가 절전 중일 때 DualSense가 다시 연결되면:
   1. CYW43 BD_ADDR를 조이콘 주소로 변경 (Broadcom 제조사 명령 `0xFC01`)
   2. 비컨 송신: ADV_IND, 20ms 간격, 3초
   3. 원래 주소로 복원
3. 주소를 바꾸는 동안에도 DualSense 클래식 연결은 유지됩니다(실기 확인).
4. 연결 불가 광고(NONCONN, 30~50ms 간격)도 시험했는데, 가끔 실패하고 반응이 늦었습니다.

### 스위치 2 독의 실제 동작 (플래시 이벤트 로그로 확인)
- **절전할 때 USB 일시중지(suspend)를 보내지 않습니다.** 대신 동글을 USB에서 떼어내고 전원을 한 번 끊었다 다시 넣으며, 이후 잠든 본체는 동글을 인식하지 않습니다.
  - 그래서 "절전" 판단은 **5초 동안 USB 인식이 안 됨**(일시중지하는 다른 호스트용으로 일시중지 3초도 포함)입니다.
  - "깨어남" 판단은 본체가 입력 보고를 다시 가져가는 것입니다.
- **깨어날 때도 USB 전원을 다시 넣습니다.** 동글이 재부팅되면서 DualSense 연결이 끊기고, DualSense는 스스로 꺼집니다. PS를 두 번 눌러야 하는 이유가 이것입니다.
- **절전 중에는 전력이 제한되는 것으로 보입니다.** 절전 중에 BLE 수신을 계속하면 동글이 재부팅을 반복했습니다. 그래서 학습은 독이 아닌 곳에서 해야 합니다. 3초 송신은 문제없었습니다.
- PS를 한 번으로 줄이는 실험(절전 중 DualSense 연결을 거절하고 비컨부터 보냄)은 실패했습니다.
  - DualSense가 첫 거절에 바로 꺼졌고, 거절 이유 0x0F와 0x0D 모두 같았습니다.
  - 기록은 `switch-wake-single-ps` 브랜치에 있고, 병합하지 않았습니다.

### RAM 제약 (중요)
- 원본 PC 모드는 core1이 Opus 인코더(약 48KB)와 디코더(약 18KB)를 힙에 할당하고 나면 **힙이 약 3.5KB밖에 남지 않습니다.**
- 고정 RAM(`.bss`)이 조금만 늘어도 core1이 부팅 중에 `Out of memory`로 멈춥니다. 그러면 BOOTSEL이 반응하지 않고 USB 인식도 실패합니다.
- 이 포크의 대응:
  - 스위치 모드에서는 Opus를 할당하지 않습니다(USB 오디오가 없으므로).
  - 매크로 녹화 버퍼와 깨우기 관련 버퍼는 스위치 모드에서만 힙에 잡습니다.
  - 저장된 매크로는 플래시(XIP)에서 바로 재생합니다.
- PC 모드 `.bss` 증가는 원본 대비 약 1.5KB입니다. 기능을 추가할 때는 `arm-none-eabi-nm build/ds5-bridge.elf | grep __bss_end__`로 원본과 비교하세요.

### BTstack 관련 주의
- 같은 RAM 이유로 BTstack은 클래식 전용입니다(`ENABLE_BLE` 없음). LE 명령은 `hci_cmd_t`를 직접 정의해서 보냅니다.
- **`ENABLE_BLE`이 없으면 포맷 문자 `'A'`(31바이트 광고 데이터)와 `'a'`, `'b'`가 컴파일에서 빠집니다.** 그러면 오류 없이 빈 광고 데이터가 전송됩니다. 그래서 광고 데이터는 `"1DDD1111111"` 형식으로 보냅니다.
- LE Meta 이벤트는 이벤트 마스크에 비트 61을 직접 켜서 받습니다.

### 플래시 배치 (`PICO_FLASH_BANK_STORAGE_OFFSET` 기준, 아래로)
| 위치 | 용도 |
|---|---|
| -4KB | 설정 (원본) |
| -20KB ~ -4KB | 매크로 슬롯 4개 |
| -24KB | 깨우기 비컨 |
| -28KB | 스위치 모드 설정 (진동 세기, 트리거 모드) |

## 빌드

원본 README의 빌드 방법을 그대로 따르면 됩니다. 이 포크는 아래 환경에서 빌드·검증했습니다.
- Pico SDK 2.3.0
- TinyUSB `2d56dc533e45e4e91b15e93fdab5e22e964f328d` (원본 CI와 같음)
- Arm GNU Toolchain 15.2.rel1
- `PICO_BOARD=pico2_w`, 150MHz

```bash
git submodule update --init --recursive
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DPICO_SDK_PATH="$PICO_SDK_PATH"
cmake --build build --target ds5-bridge   # → build/ds5-bridge.uf2
```

선택 빌드 옵션:
- `-DENABLE_SERIAL=ON`: USB 시리얼 로그.
  - 시리얼 빌드는 저장된 모드와 상관없이 **항상 PC 모드**로 동작합니다. 스위치 구성에는 시리얼(CDC) 인터페이스가 없어서, 스위치 모드면 부팅이 멈추기 때문입니다.
- `-DDS5_BLE_SCAN=ON -DENABLE_SERIAL=ON`: BLE 실험 빌드 (`src/ble_scan.cpp`).
  - 닌텐도 광고를 로그로 출력합니다.
  - 시리얼 키로 비컨을 재생합니다: `c` 연결 가능, `w` 연결 불가, `n` 동글 주소로, `l` 20초.
  - 잡은 비컨은 자동으로 플래시에 저장합니다.

## 알려진 한계
- 깨운 뒤 PS를 한 번 더 눌러야 합니다(독의 전원 동작 때문).
- 비컨 학습은 독에 꽂은 상태에서는 안 됩니다.
- 스위치로 보내는 보고 간격은 포크에서 가져온 15ms 고정입니다. 줄이려면 자이로(IMU) 샘플을 묶는 방식도 함께 고쳐야 합니다.- **절전 깨우기는 스위치 2 전용입니다.** 조이콘 2의 BLE 비컨을 쓰기 때문입니다. 스위치 1은 깨우는 방식이 달라서(클래식 블루투스) 지원하지 않습니다.
- 스위치 프로 모드는 스위치 2 독(공식)에서만 시험했습니다. 스위치 1이나 스위치 2 휴대 모드(USB-C 직결), 다른 독에서도 프로콘으로 인식될 가능성은 있지만 확인하지 않았습니다.

## 브랜치와 태그
- `main`: 이 포크의 메인 브랜치 (원본 `c67c7f6` 위에 스위치 작업을 얹은 것)
- 태그 `switch-wake-v1`: 실기에서 깨우기를 확인한 버전
- 태그 `switch-v2`: v1 + 진동 세기·트리거 모드 (실기 확인)
- `switch-wake-single-ps`: PS 한 번으로 끝내기 실험 (실패, 기록용)
